# 后端澄清记录：本地基础能力，未启用恢复执行

新增教师专用创建、读取、分类记录接口 `/api/teacher/tasks/clarifications`。仅在持久化任务试点开启时可用，当前生产开关不变。前端尚未接入，不会自动保存用户正在编辑的需求。

## 已实现

- 必须明确确认保存；确认字段严格布尔值。
- 记录绑定当前教师、学生、具体访问授权和请求 UUID；原始需求以 UTF-8 SHA256 指纹绑定，不做语义归一化。
- 数据库存储固定分类、指纹、时间、范围与决定，不存原需求正文或学生材料。指纹仍属受保护的关联元数据，不声称匿名化。
- 读取和提交重新检查教师身份及当前个案授权；他人记录返回不存在。
- 重用同一请求 ID 不重复创建；更换需求或范围返回冲突。
- 分类必须覆盖全部触发类别，值仅限禁止条件、请求动作、引用内容、尚不确定。已提交分类不可覆盖，同样内容可幂等重试。
- 24 小时逻辑有效期；下次存储操作时删除过期行。不是后台定时清理，也不保证 SQLite 磁盘页安全擦除。
- SQLite 事务串行写入。重启后可凭回执 ID 读取；作出分类时须再次提交原始需求并匹配指纹。

## 边界

验证：完整后端回归 187 项通过（151.217 秒）；最后补充权限撤销检查后的教师流程接口套件 9 项通过，存储套件 3 项通过，包含重新打开存储、原文变更冲突、幂等、分类不可覆盖、到期不可读取及原文不落库。测试为本地合成夹具，没有生产数据或真实模型调用。

成功记录分类后仍为 `review_recorded_blocked`，`can_prepare=false`。这不是批准执行，不能覆盖授权或危险动作限制，也不能证明否定语义正确。

尚未将澄清回执绑定到计划创建/执行入口。因此它只保障记录自己的所有权、范围和一致性，不阻止调用既有标准计划接口；不能宣称后端已经实现完整的“未澄清不得执行”。

下一步需要设计并测试有界的否定语义验证、原始约束到合同的映射和计划绑定，再接入 PC 操作。不能通过让教师直接选择“安全”来解除所有检查。

发布清单以后必须加入 `teacher_clarification.py` 与上一轮 `teacher_intent_guard.py`。不复用 alpha.37 的旧发布包。此轮不部署，不调用外部模型，不产生生产数据。
