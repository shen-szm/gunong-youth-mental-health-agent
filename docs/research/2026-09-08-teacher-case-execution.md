# 教师个案真实执行闭环

状态：本地实现，ENABLE_TEACHER_DURABLE_PLANS 仍默认 false，未发布；教师界面已接入，见 [教师任务界面验收](2026-09-08-teacher-task-ui.md)。

## 本轮新增

- POST /api/teacher/tasks/case-plans：创建绑定 student_id 和 access_request_id 的计划。目标参与确认摘要，使用同一幂等键更换个案会冲突。
- POST /api/teacher/tasks/durable-plans/{task_id}/execute：只执行已经人工确认且绑定个案的计划。
- GET /api/teacher/tasks/durable-plans/{task_id}/execution：查询执行状态，不触发工具或重试。
- 原 decision、delete 入口继续使用；删除及过期处理同时清理子图 checkpoint 和重试计数。不会删除原有教师报告：它仍属于既有报告生命周期，而非新增聊天副本。

首版支持 conversation_preparation / 30天 / checklist / not_needed，使用既有授权窗口，不能跨越审批截止时间。其他契约在创建真实任务时明确拒绝，不悄悄将一页简报或额外检索转换为其他内容。

## 实际工具与开源复用

复用前一阶段 LangGraph 和官方 SQLite checkpoint。新子图执行四步：

1. query_authorized_items：调用既有 student_work_product，形成/复用授权工单快照，保存工单引用。
2. check_evidence_gaps：检查工单未变化、记录结构、是否缺少主动记录/结构化自评/信息项，仅保存布尔标记。
3. render_work_product：调用既有 generate_teacher_review_report；复用原有报告持久化、结构化模型策略与安全门，不新增另一套报告算法。
4. verify_work_product：核对学生、教师、授权请求、源工单和报告哈希，保留既有证据审计的待核对状态。哈希正确不代表内容结论已经人工审核。

返回 awaiting_report_review 而非真人关怀完成。报告 PDF 继续通过现有受权限保护的下载入口获取。

## 恢复、安全与边界

- 每个业务工具及最终交付重新核对教师角色、职责分配和具体审批；任务确认本身不授予学生数据权限。授权失效后连旧执行结果也拒绝返回。
- checkpoint 仅保存工单/报告引用、哈希、布尔标记和已执行工具，不保存倾诉、学生姓名或报告正文；供应商/数据库异常在进入 checkpoint 前转换为固定错误。
- 手动重试从失败 checkpoint 继续，最多三次执行尝试；成功结果重复请求不重新生成报告。已有报告端点本身也按源工单复用，避免生成完成后进程中断导致重复报告。
- 工单在执行期间发生变化时返回冲突，需要重新创建确认任务，不在旧审批下静默换资料。
- 此版本仍是受限固定业务图，不是自由目标驱动的自主重规划；查询可能实际重复以重检源工单，界面不能将逻辑节点数解释为底层 SQL/API 调用总数。
- 执行由显式请求驱动，没有新增后台调度或自动通知；单机 SQLite 协调、生命周期主动清理和生产依赖验证限制沿用上一阶段文档。
- 原模型配置仍受既有授权规则控制；集成测试明确禁用模型外调，本轮没有新增真实学生数据或模型质量成绩。

## 验证

图执行测试覆盖正常交付、读操作无执行、副作用避免重复、故障脱敏、恢复不重跑已完成节点、三次预算、确认绑定个案及未确认拒绝。
