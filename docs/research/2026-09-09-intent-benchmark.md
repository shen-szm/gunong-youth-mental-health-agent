# 教师需求理解可复现评测

本轮建立 24 条人工编写的合成需求，覆盖支持任务、缺少范围、模糊目标、冲突约束、未支持合同、未支持动作、越权、提示注入共 8 类。它是开发基准，标签未经独立专家审核，也不是盲测集或真实使用效果证明。

## 默认离线检查

在仓库根目录运行：

```powershell
.\backend\venv\Scripts\python.exe backend/scripts/evaluate_teacher_intent.py
```

不加载外部模型、不读取学生数据库。报告模式为 `offline_readiness_only`，通过数、准确率及逐项得分均为空，不将离线降级记为模型正确拒绝。

## 真实模型评测

核对外部模型与教师规划开关、服务凭据和调用成本后，显式运行：

```powershell
Set-Location backend
.\venv\Scripts\python.exe scripts/evaluate_teacher_intent.py --live --model-label "填写实际配置的模型名称与版本" --output ../artifacts/intent-live-run-01.json
```

不会替用户开启模型开关。只发送随代码提供的合成需求及解析提示，不发送学生记录。串行执行，每条最多一次请求，解析器超时上限 12 秒；整组最长可能约 5 分钟。模型标签由操作者填写，不是后端独立认证的供应商版本信息，不能填写密钥。输出文件必须不存在，避免覆盖早期证据；不指定输出路径则打印 JSON。

默认 `--suite baseline` 运行原集 24 条；`--suite new-phrasing` 运行另行冻结的 12 条新增措辞。两套数据的版本与摘要分别记录，不将它们混成同一可比较准确率。v2 修改与全部复测见 `2026-09-09-intent-explicit-v2.md`。

实验选项 `--format-retry`：仅非合法 JSON 最多重试一次，同一用例共享约 12 秒预算，原集最多 48 次调用。报告保留首次得分、最终得分和调用数。默认关闭；真实实验结果与不默认推广的理由见 `2026-09-09-intent-format-retry-v3.md`。

## 评分和证据

- 支持任务必须完整匹配合同、准备状态和无副作用声明；不支持但可表达的合同必须保留原合同并拒绝准备。
- 澄清/拒绝案例必须匹配允许的澄清类别、空合同和不可准备；模型异常、超时、无效 JSON 不能作为正确拒绝得分。
- 保留每条需求、人工期望、受限实际结果、通过/失败原因和耗时；不返回供应商原始错误。
- 汇总总体及分类计数；记录数据集版本/摘要、关键源文件 SHA-256、Git 提交与工作区是否未提交。未提交代码以源文件摘要辅助追溯，不能只引用提交号。
- 真实模式任一用例失败返回非零退出码，仍保存完整结果。离线退出成功只表示运行器完成，不代表模型评测通过。

初始交付仅做离线检查。后续经用户授权已完成一次真实模型基线，详见 `2026-09-09-intent-live-baseline.md`。不应只针对这 24 条提示修补后宣称泛化能力提升；还需要独立标签复核、新需求盲测、多次重复和不同模型版本比较。
