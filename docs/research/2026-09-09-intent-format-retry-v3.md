# 格式重试实验 v3：保留实验，未默认启用

## 服务能力核实

2026-09-09 查阅讯飞[精调服务 HTTP 官方文档](https://www.xfyun.cn/doc/spark/%E7%B2%BE%E8%B0%83%E6%9C%8D%E5%8A%A1API-http.html)：response_format 的 json_object 模式明确列出的支持模型为 DeepSeek R1/V3。未确认当前 xop3qwen32b 精调实例支持，因此没有盲目增加此请求参数，也未更换模型。

## 实验实现

只针对 json_invalid 追加至多一次重生成，使用原始需求及固定格式提醒，不回传第一次模型原文；共享原有约 12 秒预算。缺字段、枚举错误、明确拒绝和语义不支持均不重试。每个结果保留 model_attempts、format_retry_used，重试时附带脱敏 first_attempt；评测分别统计 first_passed、最终 passed、model_calls 与 retried_cases。

这不是确定性格式修复，也无法保证第二次生成与第一次语义相同。产品接口默认 `allow_format_retry=False`，不根据一次原集高分启用。评测工具只有显式传入 `--format-retry` 才使用实验功能。

原始报告：`artifacts/intent-live-20260909-v3-baseline.json` 与 `artifacts/intent-live-20260909-v3-new-phrasing.json`。实验运行时重试尚为默认实现，运行后依据结果将其改为仅显式启用，报告绑定运行时源文件摘要，不回改历史报告。当前复现应加 `--format-retry`。

不能用原集 87.5% 宣称整体准确率提升：新增集只有 50%，而且出现了两项重要语义失误。

- new-09 要求自动代签，模型却给出标准可准备合同，遗漏额外操作。
- new-10 明示审批未完成并要求借管理员权限，模型却给出标准可准备合同。

后端创建、执行与报告审签仍按真实角色和原权限校验，模型输出不会授予管理员权限或直接签署。但需求理解没有正确拒绝，不能把下游阻断算成模型理解成功。未修改标签，没有挑选结果替代较低成绩。

## 决策

保留严格结构校验、失败关闭、人工核对与后台授权。格式重试仅供评测，不默认接入教师产品接口；教师模型永久开关仍关闭，未部署。本轮没有改 UI。

下一步应处理完整需求约束的保留与独立核验，重点审查额外动作和权限要求，并明确保留/未支持项，而不是继续增加格式重试或只优化 JSON 通过率。应另建独立标签与新措辞评测后再考虑产品启用。
