# 教师最终评审报告：开源项目与专业依据对比

更新时间：2026-08-28

## 结论

咕哝不复制电子病历，也不让教师承担诊断职责。教师端采用“授权工单 → 安全分流 → 证据映射 → 情境分析 → 支持计划 → 交叉审查 → 人工签署 → PDF”的数字员工闭环。报告只服务于校园心理健康教育、支持安排和求助导航。

## 高认可度项目对比

| 项目 | 技术与能力 | 可借鉴点 | 不直接照搬的原因 |
| --- | --- | --- | --- |
| [OpenEMR](https://github.com/openemr/openemr) | PHP/JavaScript；完整 EHR、审计、安全、FHIR；GitHub 约 5.2k stars | 细粒度访问控制、来源追踪、审计日志、不可混淆的报告状态 | 医疗场景过重，学校教师不应使用诊断式病历结构 |
| [OpenMRS Core](https://github.com/openmrs/openmrs-core) | Java；模块化医疗记录平台与可扩展数据模型 | 将数据范围、观察、计划、回访、审核拆成独立模块 | 部署与概念复杂度高，不适合直接嵌入当前轻量项目 |
| [LangGraph](https://github.com/langchain-ai/langgraph) | Python/TypeScript；持久执行、记忆、流式状态、Human-in-the-loop；GitHub 约 37k stars | 明确 Agent 状态、可暂停审阅、继续执行、失败降级与可恢复工作流 | alpha.19 先复用现有栈实现同类状态机，避免为展示而引入重依赖 |
| [MSF LIME EMR](https://github.com/MSF-OCG/LIME-EMR) | OpenMRS 3/Ozone；无国界医生维护，包含心理健康模块、报告与数据保护 | 专业模块化、数据最小化、报告与行动计划分离 | 目标是医疗人道服务，不能把临床字段直接迁移到校园端 |

## 专业内容依据

- [WHO 青少年心理健康事实清单](https://www.who.int/news-room/fact-sheets/detail/adolescent-mental-health)：报告同时关注家庭、学校、同伴、功能影响与保护环境，避免只给一个情绪分数。
- [WHO 学校健康服务指南](https://www.who.int/publications/i/item/9789240029392)：强调学校场景中的可实施支持、服务连接与质量保障。
- [WHO HAT 工具](https://www.who.int/publications/b/55043)：用于检查学校心理健康支持体系，而不是替代个体临床评估。
- [NICE NG225](https://www.nice.org.uk/guidance/ng225)：参考其对安全、保密、照护者参与、后续照护和安全计划的要求；不将风险工具或量表当成预测结论。

## 最终报告字段

1. 报告编号、版本、生成时间、授权依据、数据截止时间与教师身份。
2. 非诊断性执行摘要、风险等级、行动优先级与确定性安全裁决。
3. 数据来源计数、信息质量、缺口和“原文未发送给外部模型”的边界声明。
4. 学习、睡眠、饮食、同伴、家庭等功能影响。
5. 可回溯的风险因素、保护因素、学生意愿与证据编号。
6. 教师沟通开场、建议询问、避免事项、支持任务、负责人、时限与转介路径。
7. 3/7/15 天或按风险调整的回访安排。
8. 七个 Agent 的工具、状态、结果、冲突与最终裁决。
9. 权威证据注册表、AI 生成来源、提示词版本与降级状态。
10. 教师审核清单、修订意见、签署状态和中文 PDF。

## 落地选择

- 模型只润色去标识化结构字段中的“执行摘要”和“沟通开场”；不接收原文，不决定风险，不产生诊断和量表分数。
- 风险等级、危机处置、转介阈值、引用真实性和禁止措辞由后端确定性规则强制执行。
- 普通教师沿用申请与管理员教师审批；管理员教师直接访问。生成、查看、签署、退回和下载都写入敏感访问审计。
- 报告默认是“待教师审核”，只有完成必核清单后才能签署；Agent 工程复核不能替代持证心理专业人员审核。
