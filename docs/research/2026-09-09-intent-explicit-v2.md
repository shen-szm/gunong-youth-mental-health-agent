# 显式合同解析 v2：修复与真实复测

## 修改

新增 `ExplicitIntentContract`，继承执行合同的枚举约束，但所有字段均必填且无默认值；只用于模型解析。旧执行合同与已保存任务保持兼容。新增 `intent_version`，提示区分否定动作、禁止检索、缺失范围和模糊目标，不补造要求。

缺少字段的模型合同现在会失败关闭，不能因执行合同的默认值而变成完整候选合同。但该机制不能阻止模型自己编造一个格式合法的值，因此仍须语义评测和人工核对。

新增有限的验证错误分类，仅记录固定类型和白名单字段路径；不返回模型原文、错误上下文、非法字段名或输入值。未知字段显示 unknown。非合法 JSON 不采用字符串截取或宽松修复后冒充有效结果。

## 诊断轮失败

- 非合法 JSON：normal-2、scope-2、conflict-1、notify-1、ambiguous-3（5 条）。仅知道不是合法 JSON 文档，不能断言具体是围栏、解释文本还是截断。
- contract.period_days 枚举不合格：scope-1（1 条）。原始非法值未记录。
- 擅自补充每周跟进、一页简报、额外检索：ambiguous-2（1 条）。
- 90 天不支持任务被归为 missing_scope：unsupported-3（1 条）。

此次表现未优于首轮，不能宣称理解准确性提高；改进仅是移除隐式补值和增加可定位的安全诊断。教师模型永久开关仍关闭，未部署。新增用例失败不意味着真实学生数据被访问，所有调用仅为合成需求解析。

## 后续执行方向

1. 先核实当前服务是否支持受约束 JSON 输出或原生结构化输出；在未核实时不添加猜测的 API 参数。
2. 再评估受限的一次格式重试，并单独统计首轮通过率、修复后通过率、额外调用和语义约束保留率。不得把格式恢复当作语义正确。
3. 保留人工确认，并为时间、任务目标与资源要求补充可核对的原文依据；缺失依据应澄清。
4. 邀请独立标签复核，建立未参与改动的新集，才讨论泛化或开启试点。

本轮没有修改 UI，也没有新增后台自动任务。所有真实调用均临时启用评测进程开关。
