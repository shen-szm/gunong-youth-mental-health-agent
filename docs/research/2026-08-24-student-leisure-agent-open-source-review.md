# 学生端休闲陪伴与 Agent 工作流开源项目调研

## 调研目标

本轮不是把完整游戏移植进“咕哝”，而是回答三个问题：

1. 像素风钓鱼、种田应采用何种前端架构，才能融入现有 Vue 3 房间而不拖累首屏。
2. 宠物、小游戏与情绪支持如何组成真实的 Agent 工作流，而不是互不相关的入口。
3. 哪些项目只能参考产品思想，哪些许可证允许后续选择性复用源码。

## 落地决策

### 本轮采用

- 新增统一“休闲角”工作区，底部导航只保留一个入口；种田、钓鱼和既有治愈工具放在同一任务上下文中。
- 使用 Vue 纯状态机实现“小田园”和“慢钓台”，不新增游戏引擎依赖；状态按当前学生的本地作用域保存。
- 学生先主动选择“安静一下 / 转移注意 / 找回一点掌控 / 只是想玩”，Agent 才据此推荐玩法。游戏点击只作为交互事实，不能被解释成心理诊断。
- 右侧展示四个可核验步骤：理解选择、安全边界、安排玩法、完成后回看。步骤由确定性状态驱动，不使用虚构百分比，也不展示私有思维链。
- 每局结束只询问主观变化“轻松一点 / 差不多 / 想换一种”，生成一个低负担下一步；不自动进入教师报告。

### 暂不采用

- 不复制第三方素材、角色、地图和项目源码。
- 不引入排行榜、连续签到惩罚、失败扣分、抽卡或随机付费机制。
- 不依据种植速度、钓鱼成绩、停留时长推断焦虑、抑郁等心理状态。
- 不在本轮引入 Phaser/PixiJS；当需要可行走地图、碰撞、多场景或大量精灵时再升级游戏渲染层。

## 后续演进

1. 第二阶段可用 Phaser Vue Template 把“休闲角”升级为可行走的 2D 小庭院，但保留现有 Vue 业务层与确定性状态契约。
2. 将学生明确同意的会话小结、主动心情记录和休闲后自评交给后端 Agent 生成纵向描述性报告；游戏行为本身不作为心理风险证据。
3. 教师端只接收权限范围内、满足最少必要原则的趋势和经审批原文，不默认暴露学生私人小游戏记录。
