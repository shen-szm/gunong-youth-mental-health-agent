## 1. 项目概述

### 1.1 项目背景

青少年心理健康问题日益凸显。据《中国国民心理健康发展报告（2023-2024）》数据，14-18岁青少年抑郁检出率约为17.5%，焦虑检出率约为22.3%。传统心理咨询存在门槛高、资源不足、污名化等问题，青少年往往不愿主动寻求帮助。

与此同时，大语言模型能力持续跃升，AI正在从"对话式助手"迈向"自主执行的智能体（Agent）"。新一代Agent产品已能理解复杂意图、自主规划任务、调用工具与数据，并交付报告、表格、网页等可验收的工作成果。本项目旨在探索AI智能体在青少年心理健康领域的应用边界，构建一个低门槛、高陪伴感、安全可控的数字心理陪伴空间。

### 1.2 产品定位

- **目标用户**：12-18岁青少年（核心），教师与家长（辅助）
- **核心价值**：不诊断、不治疗、不用量表，提供倾听、情绪梳理、舒缓疗愈、求助导航
- **产品形态**：Web应用（桌面端优先，移动端兼容），像素风治愈系美术
- **技术底座**：Vue 3 + Vite + Pinia + Vue Router + FastAPI + SQLAlchemy + 讯飞星火大模型 + Phaser游戏引擎

### 1.4 安全边界声明

本项目不提供心理诊断或治疗，不生成临床量表分数，不能替代持证心理专业人员、医疗机构或紧急服务。

- 普通教师只能访问其职责范围内的学生，查看原文前必须获得管理员教师审批
- 管理员教师可直接进入支持工单，但所有敏感读取仍记录审计
- 危机信号强制覆盖普通建议，优先提示线下陪伴、可信成年人和12356/110/120
- 不把聊天正文默认发送给第三方模型；外部AI必须通过环境变量和明确同意启用
- 仓库不包含数据库、日志、真实账号、密码、API密钥、服务器地址或用户数据

### 3.2 CI/CD 流水线

**GitHub Actions 配置（.github/workflows/）**：
- 前端构建测试：`npm ci && npm run build && node --test tests/*.test.mjs`
- 后端单元测试：`python -m unittest discover -s tests -v`
- 代码质量检查：ESLint + Prettier（前端），flake8（后端）
- 安全扫描：依赖漏洞检查（npm audit / pip audit）
- 公开仓库校验：`scripts/verify-public-repo.ps1`（确保无密钥、无用户数据、无日志）

**触发条件**：
- PR到main/develop：自动运行全部测试
- push到main：运行测试 + 构建 + 发布校验
- 定时任务：每日安全扫描

### 3.3 发布流程

每次公开发布必须执行以下步骤（详见 `docs/RELEASE_PROCESS.md`）：

1. 更新 `VERSION` 文件、前端 `package.json` 版本、后端版本与 `CHANGELOG.md`
2. 执行 `scripts/verify-public-repo.ps1` 校验公开仓库（无密钥、无用户数据、无日志）
3. 创建本地不可变源码快照和 SHA-256 校验文件
4. 创建带注释的 Git 标签（格式：`vX.Y.Z` 或 `vX.Y.Z-alpha.N`）
5. 同步推送 GitHub 与 Gitee 双平台
6. 回滚仓库同步历史快照

**发布脚本不会读取或保存平台密码和访问令牌**。

#### v1.0.0-alpha.3 — 2026年1月25日 AI倾诉核心功能上线

**完成内容**：
- 文字倾诉功能：发送消息、流式回复、会话历史、明确结束确认
- 讯飞星火API接入：封装统一调用接口，支持超时重试、限流处理
- 情绪标签系统：模型输出结构化情绪标签（情绪类型+强度+证据）
- 基础安全门：关键词拦截 + 危机场景检测 + 求助路径引导（12356/110/120）
- 会话小结：结束会话时生成结构化小结（情绪轨迹、支持重点、下一步建议）
- 非诊断声明：所有回复明确标注"不构成诊断或治疗建议"

**关键技术决策（ADR-001）**：
- **决策**：模型输出必须为严格JSON格式，包含 `emotion_type`, `intensity`, `evidence`, `reply`, `risk_level` 字段
- **理由**：便于后端校验和结构化存储，避免模型自由输出带来的安全风险
- **替代方案**：自由文本输出 + 正则提取
- **取舍**：牺牲部分回复自然度，换取安全性和可解析性

**实验测试**：
- 讯飞API调用成功率：94.2%（100次测试，5次超时，1次返回格式错误）

#### v5.0.0-alpha.4 — 2026年8月18日 游戏行为情绪识别探索

**方案设计**：
- 探索从用户在游戏中的行为模式推断情绪状态的可能性
- 行为维度：
  - 潮汐沙滩：登录时间、停留区域、移动速度、收集贝壳数量、静坐时长
  - 呼吸小屋：模式选择、完成度、呼吸节奏稳定性
  - 咕团家园：互动类型、对话内容、停留时间
  - 花园状态：植物构成反映长期情绪倾向
- 实现方式：行为数据采集 → 特征提取 → 模型分析 → 情绪倾向推断 → 纳入情绪报告
- 安全边界：不从游戏成绩推断情绪，只从行为模式推断倾向，作为参考而非诊断

**关键技术决策（ADR-007）**：
- **决策**：游戏行为情绪识别作为"参考信号"，不单独作为情绪判断依据，必须与倾诉数据交叉验证
- **理由**：游戏行为与情绪的相关性尚未经过严格验证，单独使用风险高
- **替代方案**：直接用游戏行为推断情绪
- **取舍**：降低误判风险，但识别灵敏度可能不足

**实验测试（初步）**：
- 测试数据：20名测试用户，每人使用2周
- 行为特征与倾诉情绪标签的相关性分析：
  - 夜间登录频率与低落情绪相关性：0.42（中等相关）
  - 静坐时长与平静情绪相关性：0.38（中等相关）
  - 移动速度与焦虑情绪相关性：0.35（弱中等相关）
  - 咕团互动频率与积极情绪相关性：0.45（中等相关）
- 结论：游戏行为与情绪存在一定相关性，可作为参考信号，但需更多数据验证
