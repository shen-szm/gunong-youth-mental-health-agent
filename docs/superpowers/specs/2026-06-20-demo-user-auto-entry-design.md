# 演示用户免登录入口设计

## 目标

隐藏普通访问流程中的登录页面。访客打开网站时自动绑定固定演示用户并进入主界面，同时保留 `/login` 作为教师登录的隐藏入口。

## 用户流程

### 普通访客

1. 打开 `/` 或其他普通功能页面。
2. 前端发现本地没有用户身份。
3. 前端请求后端演示会话接口。
4. 后端返回固定演示用户的 ID、昵称和非教师权限标识。
5. 前端将身份写入现有 Pinia Store 和 localStorage。
6. 当前页面直接渲染，不显示登录页面。

### 教师

1. 教师手动访问 `/login`。
2. 使用现有教师账号登录。
3. 登录成功后进入 `/admin` 教师端。
4. 教师退出后返回 `/login`，该页面不会自动绑定演示用户。

### 普通访客退出

普通访客现有的“退出登录”操作将清除本地身份。随后访问普通页面时会重新绑定固定演示用户，因此不会回到可见登录流程。

## 后端设计

- 新增演示会话接口，例如 `POST /api/user/demo-session`。
- 接口按固定用户名查询演示用户；不存在时创建，存在时直接复用。
- 演示用户为普通用户，不具有教师权限。
- 返回结构与登录接口兼容：
  - `user_id`
  - `nickname`
  - `is_admin: false`
- 不在前端硬编码数据库用户 ID。
- 演示账号不依赖前端提供密码，不暴露教师权限。

## 前端设计

- User Store 新增异步方法，用于在缺少身份时获取演示会话。
- 路由守卫调整：
  - `/login` 始终允许访问，且不自动进入演示用户。
  - 普通页面缺少身份时先初始化演示会话，再继续导航。
  - 演示会话初始化失败时导航到 `/login`，作为可恢复降级路径。
- `App.vue` 不再直接挂载一份独立登录组件；页面内容统一通过 Router 渲染。
- 登录页面文件和登录、注册、找回密码能力保留，供教师隐藏访问使用。

## 数据与隐私边界

所有普通访客共享同一个演示用户，因此聊天、情绪、树洞等数据可能互相可见或相互影响。该模式只适合比赛演示、评审体验或受控展示，不适合真实用户提交隐私数据。

## 兼容性

- 保留现有登录接口、教师账号、`is_admin` 字段、`/admin` 路由和 `/api/admin` API。
- 已登录用户继续使用原身份，不会被演示用户覆盖。
- 现有 localStorage 键保持不变。

## 验证

- 演示会话接口重复调用返回同一用户。
- 演示用户始终没有教师权限。
- 无本地身份访问 `/` 时自动进入主界面。
- 直接访问 `/login` 时仍显示登录页。
- 教师登录后仍进入教师端。
- 前端生产构建与后端语法检查通过。
