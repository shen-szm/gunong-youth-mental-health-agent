# v4.5.0 宠物陪伴系统设计

## 背景

学生端目前已经有房间、每日咕哝、心情签到、倾诉、树洞和趋势查看，但宠物陪伴还没有成为核心互动。下一轮目标是让用户每天回来时能感到“有个小伙伴在等我”，同时把心情签到、倾诉、树洞等现有能力串起来。

## 目标

- 提升学生端每日打开动机。
- 让心情签到产生即时情绪反馈，而不是只保存一个状态。
- 强化“咕哝”的陪伴感和记忆点。
- 不引入复杂后端，第一版用本地状态降低风险。

## 用户体验

首页新增“咕哝小伙伴”陪伴卡，位置靠近每日咕哝卡。卡片展示宠物头像、当前状态、亲密度、连续陪伴天数和今日陪伴语。

宠物有四种状态：

- 平静：默认状态。
- 担心：用户选择“很累 / 有点烦”后出现，提供轻安抚和倾诉引导。
- 开心：用户选择“轻松 / 开心”、完成今日任务或完成宠物互动后出现。
- 困困：夜间出现，提醒休息。

每天可互动三类动作：

- 摸摸：立即得到一句短回应，今日首次摸摸增加亲密度。
- 喂点心：今日首次喂食增加亲密度。
- 说句话：打开或聚焦倾诉输入，形成真实表达。

## 状态与规则

本地 `localStorage` 保存：

- `affinity`：亲密度。
- `lastInteractionDate`：最近互动日期。
- `pettedDate`：今日是否摸摸。
- `fedDate`：今日是否喂食。
- `mood`：今日心情。
- `status`：宠物状态。
- `message`：今日陪伴语。

亲密度规则：

- 今日首次摸摸：+1。
- 今日首次喂食：+1。
- 完成今日任务：+1。
- 通过宠物入口去倾诉：+1。
- 同一天重复同类互动不重复加分，只更新回应文案。

## 与现有功能联动

- 每日心情选择后同步更新宠物状态和陪伴语。
- 完成今日任务后宠物变开心。
- 点击“说句话”复用现有倾诉面板打开逻辑。
- 新手引导完成后，宠物卡作为后续回访入口。

## 不做范围

- 不做后端同步。
- 不做宠物商店、复杂装扮、排行榜。
- 不做高频打扰弹窗。
- 不引入新依赖。

## 验收标准

- 首页出现“咕哝小伙伴”卡片。
- 用户选择不同心情后，宠物状态和陪伴语变化。
- 摸摸、喂点心、说句话三个操作可用。
- 亲密度和今日状态本地持久化。
- 测试覆盖状态规则、UI 文案、版本号和 changelog。
