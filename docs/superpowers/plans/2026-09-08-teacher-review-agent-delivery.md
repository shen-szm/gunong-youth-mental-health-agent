# 教师关怀工作 Agent：审核反馈与受限重规划实施方案

## 目标与定位

面向比赛的核心场景：教师为职责范围内学生准备一次沟通，Agent 在授权范围内整理资料、核对证据、交付报告；教师审核后，系统保留决定，后续根据反馈提出有边界的新任务。

竞争力来自可验收行动、失败恢复与授权治理，不来自装饰性思维链、多 Agent 数量或虚构使用成效。不得把报告签署标记为线下关怀完成。

## 第一阶段：精确报告在线审核（本轮已实现）

- 保留 LangGraph 持久化执行；复用既有 TeacherReviewReport、审核规则、报告决策记录与 PDF，不新增第二套审核数据库或生成算法。
- 新增精确版本读取接口 `/api/teacher/students/{student_id}/review-reports/{report_id}/detail`，同时核对当前教师、学生和审批范围。不使用 latest 代替任务报告。
- 读取和审核前校验报告内容哈希；报告展示、PDF 下载和草稿审核均拒绝被改动的内容。
- 任务执行回执新增动态 `report_status`。从报告表实时读取，不将审核意见或原文写入 checkpoint；执行完成状态与人工审核状态分别表达。
- 在线审核入口复用原组件：逐项核对、证据缺口确认、审核意见、退回或签署。任务内禁用独立重新生成，避免脱离原任务悄悄换版。
- 手机审核保留证据账本和主张追溯；本机只保存任务编号，报告正文、审核意见不进入 localStorage。
- 当前退回是记录反馈，不是 Agent 已经依据反馈改写内容；补充任务创建与反馈消费属于下一阶段。

验收：原任务在新版本出现后仍指向原报告；重复退回只有一条决策；跨学生/教师不可读取；篡改后不可读、下载、审核；签署前清单/证据门禁生效；刷新后终态保留；移动端无横向溢出。

## 第二阶段：反馈驱动的新任务（下一轮优先）

1. 定义结构化反馈类别：信息缺口、需要核对、授权范围变化、工具失败。自由文本意见留在既有报告系统，不默认外传模型。
2. 创建补充任务契约，绑定原 task_id、report_id、反馈记录及新授权摘要。原任务/原报告不可改写，新任务有独立标识与版本关系。
3. 模型只在允许的动作集中提出计划：核对资料、提示教师补充、重新验证、重新渲染；本地规则强制处理撤权和安全限制。
4. 展示新旧计划差异、变更理由和待补充项；范围变化或重新执行必须由教师确认，不能因一条退回意见自动读取更多学生数据。
5. 校验新增证据是否确实存在。不允许用同一份缺失资料反复生成并声称完成修订；无变化时清楚返回「等待补充」。

交付物：补充契约、计划差异视图、新旧任务关联、补充后报告；仍不自动触达学生、不自动作出诊断。

验收样例：缺少支持意愿 → 等待教师补充；新增授权资料 → 新计划待确认；撤权 → 停止而非重试；渲染失败 → 保留断点；无新资料 → 不伪造修订完成。

## 第三阶段：可靠性与上线门槛

- 主动清理过期 checkpoint 和本机恢复索引；明确任务与报告各自生命周期。
- 增加显式终止/重新规划操作；重试预算耗尽、源资料冲突不能永久困在不可操作状态。
- 验证生产 LangGraph 依赖、SQLite 并发限制、备份恢复和进程中断后的幂等性。
- 使用默认关闭功能开关灰度验收；满足权限、生命周期、回滚门槛后再部署。不在本轮静默启用线上试点。

## 第四阶段：比赛证据包

建议建立 100 个明确标注来源的合成任务作为初始评测集（这是待建目标，不是已有成绩）：正常30、资料不足20、工具故障20、授权变化20、重复/冲突10。训练/调参样例与最终评测样例分开。

对比普通问答、固定工作流、受限重规划；统一任务输入、权限条件、成果核验标准。记录任务完成率、交付物核验率、故障恢复率、越权阻断率、P50/P95耗时及模型调用成本，公布分母、失败案例与复现命令。

对应评分：技术可行性看故障与恢复证据；市场可行性看真实教师试用与节省工作时间；创新性看审核反馈如何进入下一轮计划；大模型结合看输入/输出契约与本地约束；赛道专业能力看完整可验收闭环。合成测试不能替代真实试用与心理效果证据。

演示顺序：含糊沟通需求 → 明确任务范围 → 教师确认 → 工具执行 → 报告证据审核 → 退回补充 → 新计划差异 → 新版交付。当前已经实现到退回/签署；后半段需第二阶段完成后才能演示为真实能力。
