# 学生倾诉、音乐与云顶暖房优化

## 复用与边界

- 播放器实际依赖 https://github.com/goldfire/howler.js 的 Howl API（2.2.4，MIT），复用加载、播放、暂停、跳转、音量与卸载能力；完整许可随前端发布。
- 参考 https://github.com/lobehub/lobehub 的对话开场与输入工作流，使用可编辑的开场建议；仅参考交互，不复制其源码或引入 React 框架。
- 云顶暖房复用本项目 gardenLifeEngine.js，而非新增另一套种植状态；通过 update:garden 回写账号隔离的本地存档。
- 沿用已经配置的讯飞精调 LoRA 接口，本轮没有重新训练模型。生产接口以合成结构化场景执行过请求，现有严格解析器接受策略输出；这不代表临床效果或自由文本质量评测。
- 外部模型继续只接收派生枚举特征，不接收学生聊天原文；最终回复由审核过的措辞构成。危机与保护性分流优先，不因对话加长而放宽。
- 音乐复用仓库已有三首房间音频，未新增下载曲库，不虚构歌手、曲名或录音授权；Howler 许可不涵盖音频录音。

## 验收

- 后端 unittest 全量测试，包含主题承接、倾听偏好、避免外部私密内容插入以及既有安全和重复回复回归。
- 前端 node 测试及 Vite 生产构建。
- RUN_EXPERIENCE_E2E=1 node --test tests/student-experience.e2e.mjs：本地隔离测试账号验证开场不自动发送、实际 API 回复、实际音频播放暂停、九格种植收获与重新进入存档恢复、390px 无横向溢出及页面无异常。
- 测试数据仅用于隔离验收，不进入生产学生统计。暖房成绩也不用于推断情绪。

## 设计依据

使用已安装的 impeccable skill，在既有房间视觉系统内提高音乐入口可发现性、对话阅读宽度、操作反馈与移动端适配；没有替换整站主题。
