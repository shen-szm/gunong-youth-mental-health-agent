# 咕哝：超级智能体赛道实施方案

日期：2026-09-07。状态：方案与选型，不代表以下能力已经实现或部署。

## 1. 决策与现状

保留 Vue/FastAPI、账号权限、讯飞 LoRA 适配、学生安全门、教师报告与现有执行可视化。新增一条考试周行动任务，不整体重写倾诉或心岛。

当前 student_support_engine.py 的 _bounded_support_contract 主要按结构化主题、风险和固定规则生成支持契约；api/student_agent.py 已具备持久化记录、过期清理、运行租约检查、查询和删除。它们是基础，不等同于支持任意任务的动态规划与断点续执行。

AgentExecutionGraph.vue 已经复用 Vue Flow，但边连接主要按计划顺序生成。新任务需返回实际依赖边、计划版本和节点运行 ID，才能准确表现分支、重试与重新规划。

## 3. 第一条端到端任务

用户：这周两门考试、三项作业，每天最多一小时，请帮我安排。

过程：安全与权限门 → 结构化澄清 → 用户确认任务数据 → 模型生成有界计划 → 工具执行 → 独立验证 → 学生验收 → 根据主动反馈修改。

规划输入限定为任务类型、匿名任务 ID、期限、可用分钟、优先级和用户确认的偏好；聊天原文留在原边界内。模糊表达无法可靠提取时展示待确认字段，不猜测、不偷偷扩大模型外传范围。

模型决定是否需要澄清、检索及使用哪些允许工具，并生成依赖关系；程序检查 schema、权限、环路、步数和预算。无效计划最多修复一次，仍失败则明确降级，不展示虚构调用。

首批工具：

1. read_confirmed_tasks：仅查询本人已确认任务。
2. build_time_plan：按期限与容量分配时间，约束不满足时返回冲突而非强行排满。
3. search_approved_resources：仅检索审核过的校内办事说明、学习方法和支持资源。
4. render_action_artifact：复用 PDF 生成器输出行动单，并生成 CSV 清单；日历导出另选成熟 RFC 5545 库，不手写转义规则。
5. verify_artifact：检查任务遗漏、时间冲突、引用存在及成果版本。
6. prepare_handoff：准备最小求助摘要，只创建待确认草稿，不自动通知教师。

每个工具统一声明输入输出 schema、访问范围、超时、错误类型、是否有副作用及幂等键。读取可有限重试，写入先查幂等记录，权限拒绝与取消不得重试。

## 4. 持久化与安全边界

- 新增独立 action-task API 和状态表，避免直接扩展旧 API 的 Literal 状态导致兼容问题。
- 任务状态包括 queued/running/waiting_input/waiting_approval/completed/failed/cancelled。成果生成完成不等于学生执行完成。
- 保存任务所有者、输入版本、计划版本、节点、工具结果引用、审批记录与成果校验值。每次恢复重新检查权限，不能凭 thread_id 获得访问权。
- 本地先用持久化 checkpoint 验证。生产 checkpointer 的数据库兼容与备份需单独评估；不假定现有 MySQL/SQLAlchemy 可直接替代官方适配器。
- 执行 worker 使用租约和幂等处理；不能只用请求内后台任务假装可跨进程恢复。进程重启后恢复未结束任务，副作用不重复。
- 初始上限：计划最多 8 步、总工具调用 12 次、重规划 2 次；单工具超时和模型 token 上限可配置，达限交付明确未完成状态。
- 用户中途修改条件时增加 input_version；旧执行返回不得覆盖新版本。审批绑定成果版本，内容变化后原审批失效。
- 删除任务同步清理 checkpoint、工具载荷、成果及检索副本；沿用现有留存期限，不额外长期保存倾诉。
- 检索资料视为数据，不执行资料中的指令；无引用不生成政策事实。教师执行和下载时重新校验授权，不能只在检索入口过滤。

## 5. 教师端和学生端交付

教师任务：根据有权查看的资料，准备本周关怀事项，列明缺失信息，先不要发送。

复用 teacher_review_engine.py 和现有 PDF 模块。交付待跟进清单、证据引用、沟通准备单、资料缺口及待审签操作。教师可修改、驳回、确认；拒绝授权时停止访问，不根据沉默或游戏成绩推断心理状态。

使用 impeccable skill 的产品界面原则：

- 学生保留房间与倾诉，新增“帮我安排一件事”；主视图显示下一步与可编辑成果，执行记录默认折叠。
- 教师先显示待处理任务及待确认事项；右侧查看成果与来源，不用新增统计大屏代替工作流。
- 执行图根据服务端真实依赖绘制；明确区分计划、运行、等待、失败和记录回看。恢复运行是单独操作，回看不触发执行。
- 390px、键盘、焦点恢复、减少动态效果、加载/空/失败/取消状态全部验收。动作名称统一为修改条件、确认计划、停止任务、查看依据和下载成果。

## 6. 分期交付与退出条件

时间为工作量估算，不是无条件承诺；依赖兼容、模型预算与真实试用安排会影响日程。

| 阶段 | 估算 | 交付内容 | 必须通过 |
| --- | --- | --- | --- |
| A 执行内核 | 2–3 开发日 | LangGraph 适配、任务契约、持久化、工具注册、审批恢复 | 进程重启后继续；重复确认不重复写入；越权恢复拒绝 |
| B 学生任务 | 3–4 开发日 | 考试周计划、条件修改、冲突说明、成果导出 | 修改可用时间后重排；不超过容量；不能完成时如实说明 |
| C 教师与检索 | 3–4 开发日 | Haystack 检索、带引用成果、授权接力与审签 | 无资料声明缺失；越权不读取；修改后重新审批 |
| D 评测与演示 | 2–3 开发日 | Promptfoo 对照、故障注入、浏览器回归、路演脚本 | 所有关键安全阻断测试通过；真实运行可复现 |

最小比赛版本为 A+B，加现有教师报告展示。C/D 不应以赶时间为由伪造完成；评测设计从 A 阶段开始，而非最后才补。

候选新增代码区域：backend/action_tasks/{schemas,graph,tools,worker,checkpoint}.py、backend/api/action_tasks.py、frontend/src/components/action-tasks/、evals/action-tasks/。先做隔离兼容验证，再决定确切依赖版本。旧倾诉安全路由保持不变，新入口用特性开关分批启用；数据库只做增量迁移并准备回滚。

## 7. 证据与比赛验收

计划建立 120 个独立测试任务：普通规划 30、信息缺失 20、条件变化 20、工具故障 20、权限与安全 20、成果一致性 10。另建开发集，不用测试集调参；数字是计划量，不是已完成结果。

固定模型、输入、资料版本和调用预算，对照普通聊天、固定工作流、动态 Agent。三组均保留相同安全限制。基础模型与 LoRA 对照作为单独实验，避免同时改变模型和工作流后错误归因。

记录任务成功率、约束满足率、工具成功率、故障恢复率、人工修改量、p50/p95 耗时、token/成本以及失败案例。成功率按预先定义的整项任务验收计算，不把大量小断言当任务样本。不可完成案例以正确说明冲突为成功标准，不以强行生成计划为成功。

发布门槛：关键越权、删除、重复副作用、安全门绕过测试必须全部通过；普通任务先测基线再设提升目标，不预填成绩。真人可用性评审盲评并记录分歧；真实试用需自愿和适当授权，单独标明样本范围，不宣称临床疗效。

五项评分证据：技术可行性给部署/恢复/成本；市场可行性给教师访谈、现有工作耗时和采购假设验证；创新性给有权限的跨角色接力及重规划对照；大模型结合给输入契约、模型选择和工具记录；赛道能力给完整任务、可编辑成果与验收回执。

路演演示只围绕一条任务：提出复杂需求 → 执行 → 当场改变约束 → 展示调整差异 → 工具失败恢复 → 验收成果 → 授权准备教师接力。清楚说明开源复用与项目新增部分，不将框架功能直接宣称自研创新。
